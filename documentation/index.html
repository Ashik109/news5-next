01 /

Installation

Run commands from the folder that contains package.json, not from the documentation folder.

Requirements

  • Node.js 20.9 or higher for this Next.js version.
  • Node.js 22.18 was used to verify this project.
  • npm and a current browser.
  • Internet access for dependency installation and the theme’s Google Fonts.

Included in the project

React pages, original images and fonts, compiled theme CSS, vendor scripts, editable content data, original SCSS reference sources and browser checks.

The original HTML template directory is not required to run or build the application.

  1. Install the locked dependencies

    npm ci

    Use npm install when intentionally changing dependencies and updating the lockfile.

  2. Start the development server

    npm run dev

  3. Open the application

    Visit http://localhost:3000/main. Your terminal displays the actual port if 3000 is already occupied.

Windows PowerShellIf PowerShell blocks npm.ps1, use npm.cmd ci, npm.cmd run dev and npx.cmd. You do not need to change the system execution policy.

04 /

Details with meaningful URLs

A slug selects a record, not just a different URL for the same hardcoded page. Card links, detail headings, primary images, metadata and product price/gallery fields are connected.

Route patternPurpose
/main/blog/[slug]Canonical blog detail layout.
/main/blog-details/[slug]Supported alias for the standard blog layout.
/main/blog-details-2/[slug]Second article layout.
/main/blog-details-3/[slug]Third article layout.
/main/shop/[slug]Canonical product detail layout.
/main/shop-product-detail/[slug]Supported alias for the standard product layout.
/main/shop-product-detail-2/[slug]Second product layout.

Replace main with another demo prefix to use the same pattern there. A record must include that demo in its demos array.

Working examples/main/blog/the-rise-of-gourmet-street-food-trends-and-top-picks
/demo-three/blog/ai-and-marketing-unlocking-customer-insights
/main/shop/disney-toys
/main/shop-product-detail-2/elegant-watch

Old URLs

Flat URLs such as /main/blog-details and /main/shop-product-detail redirect to the template’s default named record. Defaults are stored in src/data/detail-defaults.json.

Static generation & 404s

Canonical records use generateStaticParams. Alternate variants prerender their default record and can render other valid catalog slugs on demand. Unknown slugs return 404.

Demo-aware links

Use SiteLink for navigation within the selected demo. Use Link from next/link with an absolute route when deliberately switching demos.

import { SiteLink } from "@/components/DemoContext";

<SiteLink href="/blog/ai-and-marketing-unlocking-customer-insights">
  Read the article
</SiteLink>
05 /

Edit posts & products

The catalog lives in src/data/detail-catalog.json, with top-level blog and product objects. Each object is keyed by a unique slug.

Example blog record · add inside the blog object"your-new-article": {
  "kind": "blog",
  "slug": "your-new-article",
  "title": "Your New Article",
  "demos": ["main", "demo-three"],
  "images": {
    "main": "/assets/images/custom/your-article.jpg",
    "demo-three": "/assets/images/custom/your-article.jpg"
  },
  "category": "Technology",
  "author": "Your Author",
  "price": "",
  "oldPrice": "",
  "description": "A short description for this article.",
  "gallery": []
}

  1. Add the image

    For that example, save the file as public/assets/images/custom/your-article.jpg. Public asset URLs start with /assets/, not /public/assets/.

  2. Add the record and its demo membership

    Keep the object key and slug identical. Use lowercase words separated with hyphens. Include every demo where you want that record to be accessible.

  3. Add or update the card

    Edit the relevant homepage or shared archive component, including its visible title, image and SiteLink URL. Adding a catalog record does not automatically add a card to the original static listings.

  4. Verify the new page

    Open /main/blog/your-new-article, run npm run verify, then rebuild before production.

Product fields

Use "kind": "product", set price and optional oldPrice, and supply public image URLs in gallery. If a gallery is empty, the selected primary image is used. The stacked product variant displays up to the first four gallery images.

Detail data and article body are separateThe catalog controls the primary fields. The long article body and supporting template sections remain in src/components/template/BlogDetailsContent1.tsx and the other detail components. For unique full article bodies, extend the record model and render that content, or connect a CMS. Do not assume that adding a new catalog title creates a full original article.

Changing a default redirect

Edit the corresponding flat route’s page.tsx redirect target. Keep detail-defaults.json consistent for migration tooling and tests. Make sure the target record belongs to that demo.

06 /

Make the design yours

Logos & images

Shared logos are under public/assets/images/common/. Demo images have their own folders. Search the relevant header, footer or page for the exact src value before replacing a file.

Use descriptive alt text. Keep existing aspect-ratio wrappers and image classes to preserve the layouts.

Global & demo styles

src/app/globals.css provides shared application rules. The active demo’s compiled stylesheet is selected by TemplateShell from public/assets/css/theme/.

For reliable overrides, use sufficiently specific selectors and check both light/dark modes.

Find the active theme first

The route prefix and stylesheet name are not always identical. For example, /main selects demo-seven.min.css. Read the page’s theme prop before changing CSS.

Theme selection in a page/layout<TemplateShell
  demo="main"
  theme="/assets/css/theme/demo-seven.min.css"
  bodyClass="uni-body panel bg-white text-gray-900 dark:bg-black dark:text-white"
>
  {/* Page sections */}
</TemplateShell>
SCSS is not automatically compiledThe original sources are retained under src/styles/scss/, but npm run dev uses the included compiled CSS. A Sass rebuild requires configuring the original Bootstrap/Sass toolchain and its imports. Editing an SCSS file alone will not change the current site.

Headers, footers & navigation

Look at the imports in the route’s page.tsx or detail layout to identify its shared header/footer component. An edit to a shared component affects every page that imports it.

Placeholder links

Envato and ThemeForest links have been replaced with # as requested. Other intentional sample links remain in the template. Replace placeholders with your own real destinations when preparing the site for your audience.

07 /

Keep sliders working correctly

The original Swiper settings are preserved. React owns initialization and cleanup through templateSliders.ts, while the template helper parses the data attributes.

Responsive slider markup<div className="swiper-parent">
  <div
    className="swiper"
    data-uc-swiper="items: 1; gap: 16; next: .nav-next; prev: .nav-prev;"
    data-uc-swiper-s="items: 2;"
    data-uc-swiper-m="items: 3; gap: 24;"
  >
    <div className="swiper-wrapper">
      <div className="swiper-slide">Slide one</div>
      <div className="swiper-slide">Slide two</div>
      <div className="swiper-slide">Slide three</div>
    </div>
  </div>
  <button className="nav-prev" type="button">Previous</button>
  <button className="nav-next" type="button">Next</button>
</div>
Attribute / optionMeaning
items / gapVisible slides and spacing.
autoplay: 2500Autoplay delay in milliseconds.
next / prevNavigation selectors, scoped to the closest .swiper-parent.
dotsPagination element selector.
connect: .swiper-thumbsLink a main gallery to its thumbnail slider.
data-uc-swiper-xs / -s / -m / -l / -xlMinimum widths of 480 / 640 / 960 / 1200 / 1600px in the original Swiper helper.
Multiline settings must be real JavaScript stringsDo not write a literal \n inside a quoted JSX attribute. Use an expression or template string so the helper receives real whitespace.
data-uc-swiper={`items: 2;
  gap: 4;
  disable-class: last-slide;`}

Thumbnail instances initialize before connected galleries. Layout updates run after images/fonts load, responsive width changes and relevant tab events. Slider instances are destroyed when a page leaves. Avoid adding a second initializer in a page or manually replaying DOMContentLoaded.

Other interactions

useTemplateRuntime.ts manages dark mode storage, cookie notices, newsletter overlay timing, back-to-top behavior and lazy videos. UniCore supplies menus, modal windows, tabs and lightboxes.

The application keeps cacheComponents: false so inactive pages do not retain conflicting global theme styles and widget IDs in hidden page trees. React Compiler remains enabled.

08 /

Page titles & metadata

Default metadata is defined in src/app/layout.tsx. Static pages export metadata; slug pages use generateMetadata to select the record title, description and canonical route.

Static page exampleimport type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Your Page - Your Brand",
  description: "A useful description of this page.",
};

When deploying your own domain, configure metadataBase in the root metadata and review titles, descriptions, favicon, canonical URLs and social-sharing information.

export const metadata: Metadata = {
  metadataBase: new URL("https://your-domain.com"),
  title: "Your Brand",
  description: "Your site description.",
};

The favicon is src/app/favicon.ico. Avoid hardcoding the original template vendor’s domain into canonical URLs.

Connect your real services

This is a frontend template. Working modals, native validation and page navigation do not create accounts, process payments or save form submissions.

AccountsLogin, registration, reset and account modal interfaces.Authentication provider, sessions, email flows and OAuth.
Cart / checkoutOriginal cart/checkout screens and product UI.Persistent cart, stock checks, payment provider and order storage.

Keep credentials and service keys on the server. Add environment variables for the integrations you choose; the current static catalog does not require an .env file. Use NEXT_PUBLIC_ only for values that may be visible in the browser.

11 /

Build for production

npm ci
npm run build
npm run start

Use a host that supports the Next.js Node runtime and App Router, or deploy the repository through a Next.js-compatible platform. The current project is not configured as a plain static HTML export; valid alternate detail slugs can render on demand.

Hosting configuration

  • Project root: the folder containing package.json.
  • Install command: npm ci.
  • Build command: npm run build.
  • Start command for a Node host: npm run start.
  • Set integration environment variables through the hosting platform.

Before launch

  • Set your domain metadata and brand assets.
  • Replace sample content and intentional placeholders.
  • Connect the backend-dependent workflows you need.
  • Test both light/dark mode and mobile navigation.
  • Verify required routes on the deployed domain.
Documentation is separateOpen this documentation/index.html directly in a browser, or serve the folder with any static file server. It is outside public/, so the Next.js app does not expose it at /documentation by default.
12 /

Common questions

A slug returns 404.

Check the catalog key, its slug value and the demos array. The requested demo must be included. Confirm the route prefix is blog or shop (or a supported variant), then rebuild the production application.

I added a record, but it does not appear in an archive.

The original listing markup is static. Add a matching card and link in the relevant homepage/archive component, or replace that listing with a data-driven render of getDetails().

My CSS or SCSS change is not visible.

Inspect the route’s TemplateShell theme prop. The app loads compiled CSS; it does not automatically compile the retained SCSS. Check CSS specificity, browser cache and the active demo’s exact stylesheet.

A slider’s arrows control the wrong section.

Keep controls inside that slider’s closest .swiper-parent and use selectors that identify its own buttons. Preserve the .swiper-wrapper/.swiper-slide structure. Do not initialize the same instance twice.

Vertical thumbnails or mobile spacing look wrong.

Inspect multiline data attributes for literal \n sequences and use JSX string expressions instead. Check the original Swiper breakpoint suffixes; they are different from the Bootstrap-style breakpoint names used elsewhere in the theme.

React reports a hydration mismatch.

Check invalid HTML nesting and browser-only code running during server rendering. Keep vendor initialization in the page runtime after hydration; avoid inserting another copy of the original template’s head/app scripts.

A form looks valid, but nothing is saved.

Native form validation and the template’s UI are included. Accounts, search results, newsletters, payments and stored submissions need the backend integrations described in section 09.

Can I rerun the HTML conversion script?

npm run convert:template -- ../news5-html/template/src regenerates converted routes, shared template components, detail layouts and catalog data. It can overwrite manual edits. Keep a committed backup and review the changes before using it on a customized project. The original HTML source is required only for this migration command.

Does this project use Tailwind?

No. The template uses its original Bootstrap/UniCore-based styles and utility classes. Class names such as lg:... belong to the included theme utilities and do not imply that Tailwind is installed.

A useful starting pointFor a new customization, inspect one page’s imports, follow its shared components, update the relevant data/assets, and rerun the focused checks. Keep your changes small enough to compare with the original design.
